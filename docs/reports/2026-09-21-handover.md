## Start here

```bash
fermdb query review --html review.html --curator kangkon \
  --organism YAA:ORG:saccharomyces-cerevisiae-s288c
```

Open `review.html`. It holds all 95 proposals grouped by paper, strains first, with each paper's
own sentence read back out of the stored document. `j`/`k` move, `a`/`r`/`e` decide, `c` shows
the commands. Decisions live in the browser; the page writes nothing. Paste the generated
commands, then:

```bash

  --organism YAA:ORG:saccharomyces-cerevisiae-s288c --dry-run
```

## The finding that needs your decision

**The route ranker cannot recommend your own architecture.** Confirming ρ⁺ cleared C's gate and
the ranking did not move, because `rank()` separates B from C at its *third* key — a hardcoded
per-strategy constant, 0.80 for B against 0.60 for C. The chassis gate is the fourth key, so it
never crosses strategies.

Those constants encode **technique difficulty, not fit to this programme's design**. DUET chose
strategy C for reasons the constant knows nothing about. Options: make feasibility
chassis-and-programme-aware, add an explicit architectural-fit term, or accept that the ranker
answers "easiest" and read it accordingly. **This is a design decision and it is yours.**

## Two mistakes worth inheriting

**I committed with a failing test.** The gate was `pytest | tail && git commit`; a pipeline
returns the *last* command's status, so `tail` succeeding masked pytest failing. Check
`${PIPESTATUS[0]}`.

**"It renders" is not a test.** The review page showed its header and an empty list, and the
preview pane reported no console errors — because it inlines local files as `data:` URLs where
scripts never run. Executing the page's JavaScript under node found a backslash escaping a
closing backtick in seconds. A preview that cannot run scripts will tell you nothing is wrong.
